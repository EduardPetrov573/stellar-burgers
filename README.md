# Stellar Burgers

Приложение космической бургерной на React и TypeScript, созданное на основе стартового набора. Состояние приложения хранится в Redux Toolkit, навигация построена на React Router.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm ci
cp .env.example .env
npm start
```

Приложение откроется по адресу http://localhost:4000. В корневом `.env` должна быть строка:

```dotenv
BURGER_API_URL=https://norma.ffapi.ru/api
```

Локальный `.env` исключён из Git. Рабочий адрес API также указан в `.env.example`.

## Возможности

- Конструктор: выбор и замена булки, добавление, удаление и перестановка начинок, счётчики и итоговая стоимость.
- Информация об ингредиенте и заказе открывается в модальном окне при переходе из списка и на отдельной странице по прямой ссылке.
- Публичная лента заказов со статистикой и ручным обновлением по кнопке «Обновить».
- Регистрация, вход, восстановление пароля и выход. Истёкший access token обновляется через refresh token.
- Защищённые профиль и история заказов. После входа восстанавливается запрошенный маршрут.
- Профиль позволяет сохранить только изменённые поля или отменить редактирование. История заказов загружается при открытии страницы и показывает статусы заказов.
- Оформление заказа доступно авторизованным пользователям. После успешного запроса показывается номер заказа и очищается конструктор.

## Маршруты

| Адрес                                 | Страница              | Доступ        |
| ------------------------------------- | --------------------- | ------------- |
| `/`                                   | Конструктор           | Всем          |
| `/ingredients/:id`                    | Ингредиент            | Всем          |
| `/feed`                               | Лента заказов         | Всем          |
| `/feed/:number`                       | Заказ                 | Всем          |
| `/login`, `/register`                 | Вход, регистрация     | Гостям        |
| `/forgot-password`, `/reset-password` | Восстановление пароля | Гостям        |
| `/profile`                            | Профиль               | Пользователям |
| `/profile/orders`                     | История заказов       | Пользователям |
| `/profile/orders/:number`             | Заказ из истории      | Пользователям |
| `*`                                   | Страница 404          | Всем          |

### Jest

Прямые вызовы редьюсеров проверяются в `src/services/slices/__tests__`:

- `ingredients.test.ts` — начальное состояние для `UNKNOWN`, сохранение текущего состояния для неизвестного экшена, `fetchIngredients.pending`, `.fulfilled`, `.rejected`, пустой ответ, сохранение кэша при ошибке и селекторы.
- `constructor.test.ts` — начальное состояние, выбор и замена булки, добавление начинок и соусов, уникальные ID повторяющихся ингредиентов, удаление отдельного экземпляра, перестановка в обе стороны, недопустимые индексы и очистка конструктора. Проверяется, что входное состояние не изменяется.

Существующие тесты стора и обновления токена также сохранены. Сейчас выполняется 31 Jest-тест.

Команда `test:coverage` измеряет покрытие **только двух целевых слайсов** — `ingredients.ts` и `constructor.ts`. Для них задан порог 100% строк, инструкций, функций и ветвей. Это не показатель покрытия всего приложения. HTML-отчёт находится в `coverage/index.html`, LCOV — в `coverage/lcov.info`; сгенерированные отчёты исключены из Git.

### Playwright

В `tests/constructor.pl.tsx` находятся 7 сценариев страницы конструктора:

- получение каталога из HAR без обращения к серверу;
- добавление булки в верхнюю и нижнюю части;
- добавление начинки и соуса;
- открытие деталей ингредиента и закрытие крестиком;
- закрытие окна кликом на оверлей;
- оформление заказа с тестовыми токенами: проверка состава POST-запроса и заголовка авторизации, номера заказа, очистки конструктора и закрытия окна;
- сохранение бургера при ошибке сервера и успешная повторная отправка.

`tests/fixtures/ingredients.har` содержит ответ `GET /api/ingredients`, который воспроизводится через `page.routeFromHAR`. Данные пользователя и заказа находятся в `user.json` и `order.json` рядом с HAR. Изображения ингредиентов встроены в фикстуры, а незамоканные API-запросы в тестах конструктора блокируются. Реальные аккаунты и заказы не создаются. Каждый тест получает отдельный браузерный контекст.

Существующие 11 сценариев приложения тоже сохранены: всего запускается 18 браузерных тестов. Playwright сам запускает Vite с тестовым адресом API. Если сервер уже запущен, он должен использовать адрес из `.env.example`.

Можно запустить только конструктор:

```sh
npm run e2e -- tests/constructor.pl.tsx
```

По умолчанию используется Chromium, установленный через Playwright. Если в окружении уже есть совместимый браузер, путь можно передать без изменения конфигурации:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run e2e
```

## Структура

- `src/services` — слайсы ингредиентов, конструктора, пользователя, заказов и ленты, селекторы, типизированные хуки и общая типизированная фабрика thunk. Redux DevTools включён в режиме разработки.
- `src/utils/burger-api.ts` — методы HTTP API и обновление токена.
- `src/pages` — страницы, связанные с состоянием приложения.
- `src/components/ui` — переиспользуемые компоненты стартового набора.

Сборка находится в `dist`. При размещении на сервере для прямых ссылок нужно возвращать `index.html` для маршрутов приложения.
